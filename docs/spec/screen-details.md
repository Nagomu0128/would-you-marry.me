# 画面の詳細

[screens.md](../design/screens.md) の各画面について、ワイヤーフレーム・状態・操作を定義する。
見た目と動きは [design-guide.md](design-guide.md)、文言は [messages.md](messages.md)、API は [api.md](api.md) を参照。
ワイヤーフレームはスマートフォンの縦画面を表す。配置は目安で、細部はデザインガイドに従って調整する。

## 共通

### ユーザー画面の骨組み

```
┌─ ヘッダー ───────────────
│ ←  画面名（ホームではテナント名）
├─────────────────────────
│
│  各画面の内容
│
├─ フッター（ページの末尾）──
│ 利用規約 / プライバシーポリシー / お問い合わせ
├─ 下部ナビゲーション（固定）─
│ ホーム  アルバム  [＋投稿]  席次表  料理
└─────────────────────────
```

- 下部ナビゲーションは SG-03〜SG-07 で表示する。SG-01、SG-02、SG-E1 では表示しない
- 新郎新婦用ページと管理面には下部ナビゲーションはない

### 写真の拡大表示（SG-06・SC-02・SA-07 で共通）

```
（黒背景・全画面）
 ×                         保存
        ┌──────────────┐
        │              │
        │     写真     │
        │              │
        └──────────────┘
 たろう さん               ♡ 12
                          削除
```

| 操作 | 参加者 | 新郎新婦 | 管理者 |
|---|---|---|---|
| いいね・取り消し（ハートをタップ） | ○ | ×（いいね数のみ表示） | ×（いいね数のみ表示） |
| 保存 | ○ | ○ | ○ |
| 削除 | 自分の写真のみ | × | ○ |

- 左右のスワイプで前後の写真へ、下へのスワイプか × で閉じる（仮置き）
- 表示には拡大表示用の画像を使い、保存のときだけオリジナルを取得する
- 保存は Web Share API で共有メニューを開く。使えない場合はダウンロードする。アプリ内ブラウザで保存できない場合は案内を表示する（NFR-25）

### 状態の表示

| 状態 | 表示 |
|---|---|
| 読み込み中 | 内容の形をしたスケルトン |
| 通信エラー | 「通信できませんでした」と「もう一度試す」ボタン |
| 0 件 | 画面ごとの空の表示（各画面に記載） |
| 期間の終了・停止など | API のエラーに応じて SG-E1 / SC-E1 へ移動 |

## ユーザー画面（参加者）

### SG-01 参加ランディング

- サーバー側で処理してリダイレクトするため、画面としては表示されない（[api.md](api.md) の `GET /join/:tenantId`）
- 移動先: ニックネーム登録（SG-02）、ホーム（SG-03）、エラー（SG-E1）

### SG-02 ニックネーム登録・変更

```
            Welcome
     〇〇家・△△家 結婚式

  アルバムに表示する
  ニックネームを決めてください

  [ ニックネーム                ]
                          0 / 20

  [ ] 利用規約 と プライバシーポリシー
      に同意します               ← 初回のみ

  [         はじめる         ]
```

- 「はじめる」は、ニックネームが 1 文字以上で、初回は同意にチェックしたときだけ押せる
- 使用中の名前のときは、入力欄の下にエラーを表示する（`NICKNAME_TAKEN`）
- 変更のときは、見出しを「ニックネームの変更」、ボタンを「変更する」にし、同意欄は出さない。ヘッダーに戻るボタンを出す
- 成功したら、初回はホームへ移動してウェルカム演出を再生する。変更のときはホームに戻り、トーストを表示する
- API: `GET /me`、`PUT /me/nickname`

### SG-03 ホーム

```
  〇〇家・△△家 結婚式
  2026.10.31

  こんにちは、たろう さん    [変更]

  ┌ 席次表 ─────────────── > ┐
  ┌ 料理のコース ─────────── > ┐
  ┌ アルバム ─────────────── > ┐
  │  新着  [□] [□] [□]          │
  ┌ 写真を投稿する ─────────── > ┐
```

- 初めて表示したときだけウェルカム演出を再生する（再生済みかどうかはブラウザに保存する）
- アルバムのカードに新着の写真を 3 枚表示する（仮置き）
- API: `GET /me`、`GET /photos?limit=3`

### SG-04 席次表

```
  ←  席次表
  ┌──────────────────────┐
  │                      │
  │    PDF（1 ページ目）   │
  │                      │
  └──────────────────────┘
  ┌──────────────────────┐
  │    PDF（2 ページ目）   │
```

- すべてのページを縦に並べて表示し、ピンチで拡大できる（仮置き）
- 未登録のときは「席次表は準備中です」
- API: `GET /seating-chart`

### SG-05 料理のコース表

```
  ←  料理のコース
  [ 画像 1 ]
  [ 画像 2 ]
```

- 画像を登録順に縦に並べる。タップで拡大表示（保存・いいねはなし）
- 未登録のときは「コースのご案内は準備中です」
- API: `GET /course-menu`

### SG-06 共有フォトアルバム

タイムラインタブ:

```
  ←  アルバム
  [ タイムライン | ランキング ]
  ( すべて )( 自分の投稿 )
  [□][□][□]
  [□][□][□]     ← 各写真の右下に ♡ いいね数
  [□][□][□]
  （下へスクロールすると続きを読み込む）
```

ランキングタブ:

```
  [王冠] 1 位
  ┌──────────────────────┐
  │        写真           │
  └──────────────────────┘
  たろう さん            ♡ 32

  2 位 [写真]     3 位 [写真]
  4 位 [□] はなこ さん    ♡ 18
  ……
  10 位 [□] ……
```

- タイムラインは新しい順。画面を下に引っ張ると最新の状態に更新する（D-24）
- 「自分の投稿」では自分の写真だけを表示し、「あと 88 枚投稿できます」と表示する
- ランキングは、表示するたびに 3 位 → 2 位 → 1 位の順に登場する演出を再生する
- 写真をタップすると拡大表示
- 0 件のとき: タイムラインは「まだ写真がありません。最初の 1 枚を投稿しましょう」と投稿ボタン、ランキングは「まだいいねされた写真がありません」
- API: `GET /photos`、`GET /photos/ranking`、`PUT` / `DELETE /photos/:photoId/like`、`DELETE /photos/:photoId`

### SG-07 フォトアップロード

```
  ←  写真を投稿

  ┌──────────────────────┐
  │  [カメラ]  撮影する    │
  │  [画像]    写真を選ぶ  │
  └──────────────────────┘
  あと 88 枚投稿できます

  （選んだ後）
  ┌──────────────────────┐
  │      プレビュー        │
  └──────────────────────┘
  [         投稿する         ]
  送信中  ████████░░░░  60%
```

- 1 回に 1 枚（D-12）。「撮影する」はカメラを起動し、「写真を選ぶ」は端末の写真から選ぶ
- 選んだ時点で形式とサイズ（10MB）を確認し、問題があればエラーを表示する
- 送信中は進捗を表示する。失敗したら「もう一度送る」ボタンを出す（NFR-10）
- 完了したら完了の演出を再生し、「続けて投稿する」「アルバムを見る」を表示する
- 上限に達しているときは、選ぶボタンを押せなくして「投稿できる枚数（100 枚）に達しました」と表示する
- API: `GET /me`、`POST /photos`

### SG-E1 エラー

```
          [アイコン]

   参加の受付期間ではありません

   受付は結婚式の当日と翌日です。

   [ お問い合わせ ]
```

- 表示する文言はエラーの種類（`code`）ごとに [messages.md](messages.md) で定める
- 下部ナビゲーションは表示しない

## 新郎新婦用ページ

### SC-01 パスコード入力

```
         For the Couple
     〇〇家・△△家 結婚式

  管理者からお伝えした
  パスコードを入力してください

  [ パスコード                  ]

  [ ] 利用規約 と プライバシーポリシー
      に同意します               ← 初回のみ

  [           入る           ]
```

- 間違えたときは「パスコードが違います（あと 3 回）」のように残りの回数を表示する
- ロック中は入力欄とボタンを押せなくし、待ち時間を表示する
- 初めて入ったときは、お祝いの演出を再生してから写真一覧を表示する
- API: `GET` / `POST /api/couple/:tenantId/login`

### SC-02 写真一覧

```
  〇〇家・△△家 結婚式
  [ すべての写真 | ランキング ]
  投稿者: [ すべて ▼ ]
  [□][□][□]
  [□][□][□]
```

- 「投稿者」を押すと、下から投稿者の一覧（ニックネームと枚数）が出て、選んだ人の写真だけを表示する
- ランキングは参加者と同じ表示
- 拡大表示では保存だけができる
- 0 件のときは「まだ写真がありません」
- API: `GET /photos`、`GET /photos/ranking`、`GET /uploaders`

### SC-E1 エラー

- SG-E1 と同じ形。文言は新郎新婦向けのもの（[messages.md](messages.md)）

## 管理面

管理面もスマートフォンで操作できるようにする（NFR-24）。一覧は縦に並ぶカードで表示する。

### SA-01 ログイン

```
     would-you-marry.me 管理

     [ Google でログイン ]

  （許可されていないアカウントのとき）
  このアカウントでは管理画面を利用できません
```

### SA-02 テナント一覧

```
  テナント                 [＋ 作成]
  ┌──────────────────────────┐
  │ 〇〇家・△△家 結婚式         │
  │ 2026-10-31   [参加受付中]   │
  │ 参加者 52 / 写真 830         │
  └──────────────────────────┘
  ┌──────────────────────────┐
  │ ……                         │
  └──────────────────────────┘
  [ 監視 ]
```

- 期間はラベルで表示する: 準備中 / 参加受付中 / 閲覧期間 / 新郎新婦のみ / 削除済み。停止中は「停止中」を優先して表示する
- API: `GET /api/tenants`

### SA-03 テナント作成

```
  ←  テナントの作成
  テナント名  [                    ]
  開催日      [ 2026-10-31         ]
  [          作成する          ]
```

- 作成したらテナント詳細（SA-04）へ移動する
- API: `POST /api/tenants`

### SA-04 テナント詳細・設定

```
  ←  〇〇家・△△家 結婚式
  期間: 参加受付中（11/1 まで）
  データの削除予定日: 2027-05-01
  [ 停止する ]

  基本情報               [編集]
  席次表 PDF     [差し替え][確認]
  コース表の画像  2 枚    [編集]
  URL の発行                  >
  写真管理                    >
  参加者管理                  >
  参加者画面のプレビュー        >

  利用状況
  参加者 52 / 写真 830 / いいね 2,140 / 3.2GB

  [ このテナントを削除する ]   ← Error 色
```

- 停止・再開は確認ダイアログを出す
- 削除はテナント名の入力を求めるダイアログを出す
- コース表の画像の編集では、追加・削除・並べ替え（ドラッグ）ができる
- API: `GET` / `PATCH /api/tenants/:tenantId`、席次表・コース表の API、`POST /api/tenants/:tenantId/deletion`

### SA-05 URL の発行

```
  ←  URL の発行

  参加 URL（QR コード）
  ┌────────────┐
  │  QR コード  │
  └────────────┘
  https://would-you-marry.me/join/…  [コピー]
  参加できる期間: 10/31 0:00 〜 11/1 23:59
  [ QR コードを保存 ]  [ 再発行 ]

  新郎新婦用 URL
  https://would-you-marry.me/couple/…  [コピー]
  [ 発行 / 再発行 ]
  パスコード: AB12CD34  [コピー]   ← 発行した直後だけ表示
  ※ パスコードはこの画面を離れると再表示できません
```

- QR コードは印刷用に 1,024px 四方の PNG で保存する（仮置き）
- 再発行は確認ダイアログを出す
- API: `GET` / `POST /api/tenants/:tenantId/join-url`、`GET` / `POST /api/tenants/:tenantId/couple-access`

### SA-06 監視

```
  ←  監視
  テナント       参加者  写真  いいね  容量
  〇〇家・△△家     52    830  2,140  3.2GB
  ……
  [ 外部の監視ツールを開く ]
```

- API: `GET /api/tenants`

### SA-07 写真管理

```
  ←  写真管理
  [□][□][□]
  [□][□][□]
```

- タップで拡大表示し、そこから削除する（確認ダイアログあり）
- API: `GET /api/tenants/:tenantId/photos`、`DELETE /api/tenants/:tenantId/photos/:photoId`

### SA-08 参加者画面のプレビュー

```
  ←  プレビュー
  [ ホーム | 席次表 | 料理 ]
  ┌──────────────┐
  │ スマートフォン  │
  │ 幅の枠の中に    │
  │ 参加者の画面    │
  └──────────────┘
```

- ゲスト用の画面部品（`packages/ui`）で表示する。リンクやボタンは押せないようにする
- ニックネームは「プレビュー」と表示する

### SA-09 参加者管理

```
  ←  参加者管理
  たろう       12 枚   [変更]
  はなこ        3 枚   [変更]
```

- 「変更」でニックネームを入力するダイアログを出す
- API: `GET /api/tenants/:tenantId/guests`、`PATCH /api/tenants/:tenantId/guests/:guestId`
