# 寿ぎ（Kotohogi）— デザインシステム

参加者・新郎新婦・管理者に共通する UI の基準。2026-10-21 に「The Wedding Journal」を廃止し、ゼロから再構成した。
実装の正本は `packages/ui/src/theme/`（トークンと土台）、`packages/ui/src/ornaments/`（水引・折り鶴・文様）、`packages/ui/src/motion/`（演出）。画面の機能・API・権限・文言の意味は従来の仕様（screen-details.md・messages.md）のまま。

## 方向性

**和の婚礼の紙ものを、手のひらで受け取る体験にする。** 招待状、芳名帳、席札、御品書き、祝儀袋。日本の披露宴で手に取る紙ものの品格と華やぎを、スマートフォンの画面に置き換える。

- 素材は、生成りの和紙、墨、紅、金箔、水引。余白を広く取り、金は細く、紅は要所にだけ使う。豪華さは「量」ではなく「仕立て」で出す
- 一日のための、おふたりの画面にする。アプリの名前ではなく、おふたりの名前と式の日付を主役にする
- 演出は「紙が折られ、結ばれ、開かれる」動きで統一する。記帳した紙が折り鶴になって飛び立ち、屏風が開いておふたりの名前が現れる
- 管理画面は同じ紙と文字でつくる「準備帳」。演出は控え、一覧性と確実な操作を優先する

### やらないこと（AI 的な定型の排除）

次の表現は使わない。旧デザインで「AI が作った画面」に見えた原因になっていた。

- 大文字で字間を空けた英字の小見出し（`YOU ARE INVITED`、`COLLECTED MEMORIES` など）。英字の装飾見出し全般
- 英字のイタリック体の決まり文句（`Welcome to our day.`、`With love, for this day.` など）
- 「01 / はじめに」のような番号付きの段落見出し
- 二重罫の白い箱を縦に積むだけの構成。どの画面も同じ「カード＋見出し＋説明」の繰り返し
- 何にでも 500〜600 の中間ウェイトを当てること。ウェイトは 2 段の対比で使う（後述）
- 細線アイコンを四角い枠に入れて並べるだけのナビ・入口。アイコンは補助に留め、文字と紙の形で導線をつくる
- 絵文字、紫や青のグラデーション、すりガラス、ネオン、過剰な角丸と影
- 蝶結び（リボン）の意匠。結婚式は一度きりのお祝いなので、水引は**結び切り（あわじ結び）**だけを使う。お祝いの縁起に反する意匠（割れ・切れ・別れを連想させるもの）も避ける

## 文字

Web フォントを自前で配信する（`packages/ui/src/theme/fonts.css`、fontsource）。日本語は unicode-range で分割され、画面で使う文字の分だけ読み込む。`font-display: swap` で、フォントを待たずに表示する。外部 CDN からは読み込まない。

| 役割 | 書体 | ウェイト | 用途 |
|---|---|---|---|
| 明朝 `--font-mincho` | しっぽり明朝 B1 | 500 / 800 | 見出し、式の言葉、おふたりの名前、案内の本文 |
| ゴシック `--font-gothic` | Zen Kaku Gothic New | 400 / 700 | 操作、ラベル、入力、補足、管理画面の本文 |
| 筆 `--font-brush` | Yuji Syuku | 400 | 記帳した名前、署名、印の文字 |
| 数字 `--font-numeral` | Bodoni Moda | 可変 | 日付、順位、枚数などの数字だけ |

- ウェイトは**明朝 500 / 800、ゴシック 400 / 700 の 2 段だけ**を使う。中間（600 など）を使わない。強調は太さの対比、大きさ、色、字間でつける
- 明朝の見出しは字間 `0.12em`（`--tracking-wa`）、大きな表紙の文字は `0.24em` まで。ゴシックの本文は字間を詰めない
- 式の名前・見出しの装飾には縦書き（`tategaki` ユーティリティ）を使ってよい。操作・入力・長い文には使わない
- 英字は日付・数字・ブランド上必要な最小限に留める。英字だけの見出しを作らない
- 文字は rem、行高は単位なし。本文 1rem、補足 0.875rem、キャプション 0.75rem。入力は 1rem 以上（iPhone の拡大を防ぐ）
- 意味のある見出し・名前は折り返し、長い名前（20 文字）でも横にはみ出さない

## 文言のトーン

- です・ます調。式の場にふさわしい、控えめで温かい敬語（「ようこそお越しくださいました」「お席をご確認ください」）
- 装飾の言葉も日本語で短く。英語のキャッチコピーを作らない。季語や漢語（「寿」「御席次」「御献立」）は見出しの装飾に使ってよいが、操作のラベルは平易な言葉にする
- 画面に出す文言は `packages/ui/src/messages/ja.ts` にだけ置き、[messages.md](messages.md) にも同じ文言を載せる

## 装飾（ornaments）

`packages/ui/src/ornaments/` の SVG を使う。画像ファイルを増やさない。

- **水引 `MizuhikiKnot`**：あわじ結び。金と紅の 5 本どり（`strands="five"`）。48px 未満は `one`、中くらいは `three`。交差の切れ目は背景色で描くので、置く面の色を `--knot-gap` に渡す。濃い面では `tone="on-dark"`
- **折り鶴 `Orizuru`**：面ごとの陰影を持つ横向きの鶴。`tone` は `kinu`（生成り）・`beni`（紅）・`kin`（金）・`line`（線だけ）
- **文様**：青海波、和紙の繊維。金の細罫は `.wa-kin-rule`（中央に菱）
- 装飾の SVG は `aria-hidden`。意味を持たせない

## レイアウトと部品

- 参加者・新郎新婦は最大 40rem、管理は最大 76rem（64rem 以上で左に管理ナビ）。参加者の画面は 48rem 以上で、紙の外側を臙脂や文様の「卓」にして、一枚の紙として見せてよい
- 左右余白は 1.5rem、狭いモバイル（22rem 以下）は 1rem。セーフエリアを考慮する
- 主要ボタンは最小高 3.25rem。固定高にせず、文字の拡大で伸びる。タッチ対象は 2.75rem 以上
- 角丸は小さく（操作 0.25rem、紙 0.375rem）。影は紙が浮く程度の薄いものだけ（`--shadow-card` / `--shadow-lift`）。区切りは余白・罫・紙の重なりでつくる
- 写真一覧は 3 列、4:5 の枠（管理画面の広い画面だけは、確認しやすいよう列を増やす）。閲覧時は写真本来の比率で全体を表示する
- 利用できる操作を色だけで区別しない。選択状態には下線・印・塗り・文言を併用する

### 画面ごとの見立て

| 画面 | 見立て |
|---|---|
| ニックネーム登録 | 受付の**芳名帳**。名前を書くと筆文字で記帳され、紙が**折り鶴**に折られて画面の上へ飛び立つ |
| ホーム | **招待状と式の表紙**。臙脂と青海波の表紙、縦書きのおふたりの名前、金の日付、水引。写真を贈る入口は**祝儀袋**、席次表・料理は**席札・御品書き** |
| 席次表・料理 | **席次表・御品書き**の紙として、額装したように見せる |
| アルバム・ランキング | 紙焼き写真の**写真帖**。一位は金の額縁と水引の飾り |
| 投稿 | 写真を一枚、紙に貼って**朱印**を押す |
| 新郎新婦 | おふたりに宛てた**祝いの包み** |
| エラー・規約 | 同じ紙の上で静かに伝える。装飾は控える |
| 管理画面 | **準備帳**。紙と文字は共通、演出は控えめ |

## モーション

Motion（`motion/react`、`LazyMotion` + `m`）と CSS で作る。動画・Lottie・大きな画像素材は使わない。演出は SVG とトークンの色だけで描く。

| 場面 | 演出 | 長さ |
|---|---|---|
| ニックネーム登録 | 芳名帳に筆文字で記帳 → 紙が折られて折り鶴になる → 羽ばたいて画面の上へ飛び立ち、金の粒が残る | 送信から約 2.6 秒 |
| 初回ホーム | 金屏風が閉じた状態から、中央に水引が結ばれ（線が描かれる）、屏風が左右に開いておふたりの名前と日付が現れる。金箔が舞う | 最大 3.6 秒 |
| 新郎新婦の初回入室 | 二羽の鶴が左右から舞い込み、寄り添う軌跡を描く。紙吹雪とともにおふたりの名前 | 最大 3.6 秒 |
| 投稿完了 | 写真が紙に置かれ、「寿」の朱印が押される（押印の衝撃と滲み）。紅・金・白の紙吹雪 | 最大 2.4 秒 |
| いいね | ハートが弾み、梅の花びらと金の粒が散る | 0.9 秒 |
| ランキング | 三位から一位へ登場。一位の金の額縁に光が一度走り、水引の飾りが結ばれる | 一位まで約 2 秒 |
| 画面の切り替え | 紙を送るような短いフェードと位置の変化（巻物が開くような clip-path も可） | 0.35 秒以内 |
| タブ・ナビ | 選択の印（金の菱）が滑って移る | 0.3 秒 |
| 読み込み | 水引が結ばれていく線の繰り返し、または羽ばたく鶴 | 繰り返し |
| スクロール | ホームの各段が初めて画面に入るときに一度だけ立ち上がる | 0.5 秒 |

原則:

- 動かすのは主に transform・opacity・clip-path。SVG の線描画（pathLength）と、小さな SVG の形の変化（折り鶴の面）は例外として認める
- 全画面の演出はスキップを常に表示し、画面のどこをタップしても飛ばせる。Escape でも飛ばせる。飛ばしたら即座に通常画面に戻る
- 記帳の演出は送信の処理と並行して進め、通信を待たせない。送信に失敗したら折りを開いて紙に戻し、エラーを表示する
- `prefers-reduced-motion` では演出を省き、結果の状態だけを表示する。通常操作の大きな移動もやめてフェードにする
- 常時動き続ける装飾は、読み込み中の表示と、ホームの表紙のごく控えめな金のきらめき（8 秒以上の周期、画面外では止める）だけ。点滅（1 秒に 3 回以上の明滅）はしない
- 演出の長さは `packages/ui/src/motion/durations.ts` に集める

## 読み込みとブラウザ

- CSS は各アプリの `index.css` から一度だけ読み込む。テーマの `index.css` が、フォント・装飾・部品・画面・演出の CSS を決まった順で取り込む。JS モジュールから CSS を読み込まない（cascade layer の順序が変わる）
- CSS のファイルは担当ごとに分ける: `theme/components.css`（共通部品）、`theme/guest.css`（参加者・新郎新婦の画面）、`theme/admin.css`（管理画面）、`motion/ceremony.css`・`motion/micro.css`・`motion/orizuru.css`（演出）、`ornaments/ornaments.css`（装飾）
- 席次表、投稿、アルバム、新郎新婦画面、管理機能はルート単位で遅延読み込み。PDF 本体と worker は席次表を開いたときだけ必要とする
- ホームの新着写真を待たずに、式の案内と主要操作を表示する。一覧の最初の 6 枚は通常読み込み、それより下は native lazy loading。写真枠を先に確保する
- 全画面の保存時だけオリジナルを取得する既存方式を継続する。動的モジュールの取得失敗にも再読み込み操作を表示する
- 高さは vh のフォールバックと dvh。レイアウトは Grid/Flex、モーダルは native dialog。View Transitions や anchor positioning に必須機能を依存させない
- Safari 系と Chromium 系で確認する。エンジンのテストを実機検証と同一視しない

## アクセシビリティ

- モーダルは `showModal()` で背景を操作対象から外す。閉じると起点にフォーカスを戻す
- 写真にはスワイプに加えて、前後ボタン・矢印キー・閉じるボタンを用意する
- 管理画面と参加者画面に本文へのスキップリンクを置く
- フォームは可視ラベルとエラーの関連付けを持つ。芳名帳のように見た目を変えた入力欄も、実体は `label` 付きの `input` にする。非表示のファイル入力は操作ボタンから起動する
- 写真の代替テキストは投稿者名から生成。装飾の水引・鶴・文様は読み上げない。演出の結果（「記帳しました」など）は必要に応じて live region で伝える
- 縦書きの装飾見出しは、読み上げ順が崩れないよう DOM 上は通常の見出しとして置く
- スケルトン、空の状態、再試行、送信進捗、投稿上限、認証エラーを通常画面と同じルールで表示する
- 文字サイズ 200%、幅 320px で横にはみ出さない。コントラストは WCAG 2.1 AA
