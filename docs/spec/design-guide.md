# The Wedding Journal — デザインシステム

参加者、新郎新婦、管理者に共通する UI の基準。2026-10 の全面再構成で、旧デザインを置き換えた。
実装の正本は `packages/ui/src/theme/index.css`。画面の機能・API・権限は従来のドメインモデルを使う。

## 方向性

一日のための招待状と、一生残る写真帳。生成りの紙、深緑のインク、朱色の印、細い罫線を使い、結婚式の印刷物とつながる画面にする。英字は情緒を添える装飾・副題に使い、操作と案内は日本語で示す。

ホームは式の表紙、写真を残す導線、当日の案内、みんなのアルバムの順。受付の QR コードから参加した人が、席次表・料理・投稿を固定ナビからすぐに開ける。写真がまだなくても、表紙と案内は完成した状態で表示する。

管理画面は同じ紙と文字の「準備帳」。PC は左側に管理ナビ、モバイルでは上部に配置する。ログイン、一覧、作成、詳細、URL 発行、写真、参加者、プレビュー、利用状況の全画面で同じ基礎部品を使う。

## 色と文字

| トークン | 値 | 用途 |
|---|---|---|
| paper | `#F5F2EB` | 全体の紙色 |
| surface | `#FFFEFA` | 招待状、フォーム、シート |
| ink | `#25483F` | 本文、主要操作、見出し |
| muted | `#5E6961` | 補足文 |
| rule | `#D8DDD3` | 区切り線 |
| accent | `#A64D3C` | 朱色の印、リンク、装飾 |
| tint | `#E8EDE5` | 補足の面、状態表示 |
| error | `#A23532` | エラーと危険な操作 |
| viewer | `#15241F` | 写真の全画面表示 |

- 本文と入力は端末のゴシック体。和文の見出しは端末の明朝体、英字は Iowan / Palatino / Georgia 系。
- 外部 Web フォントを読み込まない。フォント待ちを初回表示の条件にしない。
- 文字は rem、行高は単位なし。本文 1rem、補足 0.875rem、キャプション 0.75rem。入力は 1rem 以上。
- 英字の装飾見出しは clamp で調整。意味のある見出し・名前は折り返し、長文でも横にはみ出さない。

## レイアウトと部品

- 参加者・新郎新婦は最大 40rem。管理は最大 76rem、64rem 以上でサイドナビを表示。
- 通常の左右余白は 1.5rem、狭いモバイルでは 1rem。セーフエリアも考慮する。
- 主要ボタンは最小高 3.25rem。固定高にせず、文字を拡大したときにも伸びる。
- タッチ操作は原則 2.75rem 以上。タブ・絞り込み・前後の写真・閉じる操作にも適用する。
- カードの角丸は 0.5rem、入力・ボタンは 0.375rem。影を主な区切りにせず、余白と罫線で整理する。
- 写真一覧は 3 列、4:5 の枠。閲覧時は写真本来の比率で全体を表示する。
- ホームの新着は紙焼き写真のように並べる。ランキングは一位を大きく、二・三位を並列、残りは行にする。
- 利用できる操作を色だけで区別しない。選択状態、下線、ラベル、ハートの塗りを併用する。

## モーション

`packages/ui/src/motion/` の SVG と Motion を使う。動画、Lottie、大きな画像素材は使わない。

| 場面 | 演出 |
|---|---|
| 初回ホーム | 結び目と植物の線画を添えた招待状 |
| 新郎新婦の初回入室 | おふたりに向けた記念の招待状 |
| 投稿完了 | 記念印とチェックの描画 |
| いいね | 朱色のハートと短い放射線 |
| ランキング | 三位から一位へ登場、一位にロゼット |
| 画面・タブ | 短いフェードと位置の変化 |
| 写真を開く | 選んだ写真の位置から拡大 |
| 確認シート | 下から短く登場 |

- 主に transform と opacity を動かす。小さなチェックの SVG 線描画は例外。
- 初回演出は最大 2.8 秒。スキップを常に表示し、背後の操作をブロックしない。
- `prefers-reduced-motion` では演出を省略し、通常操作の大きな移動も止める。
- 常時動き続ける装飾・自動カルーセル・点滅は使わない。

## 読み込みとブラウザ

- CSS は各アプリの `index.css` から一度だけ読み込む。Motion の CSS も共通テーマから取り込む。JS モジュールから別に読み込むと cascade layer の順序が変わるため避ける。
- テーマ・基礎・部品・ユーティリティのレイヤー順を保つ。
- 席次表、投稿、アルバム、新郎新婦画面、管理機能はルート単位で遅延読み込み。PDF 本体と worker は席次表を開いたときだけ必要とする。
- ホームの新着写真を待たずに、式の案内と主要操作を表示する。
- 一覧の最初の 6 枚は通常読み込み、それより下は native lazy loading。写真枠を先に確保する。
- 全画面の保存時だけオリジナルを取得する既存方式を継続する。
- 動的モジュールの取得失敗にも、再読み込み操作を表示する。
- 高さは vh のフォールバックと dvh。レイアウトは Grid/Flex、モーダルは native dialog。最新の View Transitions や anchor positioning に必須機能を依存させない。
- Safari 系と Chromium 系で確認し、実機・低速回線の検証は別途行う。エンジンのテストを実機検証と同一視しない。

## アクセシビリティ

- モーダルは `showModal()` により背景を操作対象から外す。閉じると起点にフォーカスを戻す。
- 写真にはスワイプに加えて、前後ボタン・矢印キー・閉じるボタンを用意する。
- 管理画面と参加者画面に本文へのスキップリンクを置く。
- フォームは可視ラベルとエラーの関連付けを持つ。非表示のファイル入力は操作ボタンから起動する。
- 写真の代替テキストは投稿者名から生成。装飾の紋章・線画は読み上げない。
- スケルトン、空の状態、再試行、送信進捗、投稿上限、認証エラーを通常画面と同じルールで表示する。
