# UI 全面再構成と検証

2026-10-21。デザインの基準は [The Wedding Journal](spec/design-guide.md)。

## 対象画面

| 利用者 | 確認対象 |
|---|---|
| 参加者 | ニックネーム登録・変更、ホーム、席次表、料理、アルバム、ランキング、投稿 |
| 新郎新婦 | ログイン、写真一覧・投稿者の絞り込み |
| 共通 | エラー、利用規約、プライバシーポリシー、写真閲覧、確認ダイアログ |
| 管理者 | ログイン、一覧、作成、詳細、URL 発行、写真、参加者、プレビュー、利用状況 |

QR の参加ランディングは従来どおりサーバー側で認証・リダイレクトする。

## 実装

- 生成り、深緑、朱色と印刷物のような文字・罫線を基礎に、全画面と共通部品を再構成。
- スマートフォン向けの固定ナビ、写真を残す導線、席次・料理の案内。管理者には同じ意匠の準備帳を用意。
- 専任のモーション担当が SVG の結び目、招待状、記念印、いいね、ランキングの演出を制作。
- 外部フォントを廃止。画面を分割読み込みし、ホームは新着写真の取得完了を待たずに操作可能にした。
- ネイティブ dialog、写真の前後ボタン、キーボード操作、動きを減らす設定、文字拡大を対応。
- CSS レイヤー順の競合、Tailwind のクラス名と固定ナビの衝突、PDF の中断済み描画の再開を修正。

## ブラウザ確認

ローカル開発サーバーを Playwright の Chromium と WebKit で確認。API は架空の式・写真を返すモックで置換し、実データを変更しない。

- 21 画面・状態 × 2 幅（320 / 390 CSS px）× 2 エンジン、計 84 ケースで横はみ出しとページ例外なし。
- 管理画面 9 ページを幅 1440px でも目視確認。
- Chromium の幅 390px で axe の WCAG A / AA / 2.1 AA 検査を実施し、検出違反なし。
- 写真の前後移動、Tab、Escape、管理の確認シート、新郎新婦の投稿者絞り込みを両エンジンで確認。
- 文字サイズ 200% のホーム、初回演出のスキップ、reduced motion、写真上の削除確認を両エンジンで確認。
- 新着写真の通信失敗時もホームと投稿導線が表示され、ホームでは PDF モジュールを取得しないことを確認。
- 実際の PDF をモック配信し、両エンジンの canvas 描画とナビが画面最下部に固定されることを確認。

ブラウザエンジンによる検証であり、iPhone・Android 実機や式場の回線での測定ではない。自動アクセシビリティ検査はスクリーンリーダーによる手動検証を代替しない。

## リポジトリの検証コマンド

最終実行ですべて成功。テストは 57 ファイル・924 件（shared 54、UI 99、DB 94、guest 405、admin 272）。

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
git diff --check
```

新着写真の遅延・通信失敗でも主要導線を表示する回帰テストを追加した。検証用画像やモックは製品の配信物に含めない。
