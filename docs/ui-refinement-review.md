# UI の再構成（寿ぎ）と検証

2026-10-22。デザインの基準は [寿ぎ（Kotohogi）](spec/design-guide.md)、決定の記録は [ADR-0004](adr/0004-wa-wedding-redesign-and-self-hosted-fonts.md)。
2026-10-21 の「The Wedding Journal」を廃止し、ゼロから組み直した。

## 再構成の理由

旧デザインは次の点で「AI が作った画面」に見えていた。

- 大文字で字間を空けた英字の小見出し（YOU ARE INVITED など）と、英字イタリックの決まり文句（Welcome to our day. など）
- 端末のフォントに、中間ウェイト（500・600）を多用
- 二重罫の白い箱を縦に積むだけの、どの画面も同じ構成
- 演出が白い箱のフェードだけ。印が蝶結び（結婚式には使わない結び方）

## 進め方

土台（トークン・フォント・装飾・CSS のファイル分割・デザインガイド）を先に作り、担当ファイルが重ならないよう 5 つに分けて、サブエージェント（`.claude/agents/motion-artist.md`・`ui-designer.md`）が別々の worktree で並行して作った。統合で、ファイル間の約束（いいね・ランキングのクラス、確認シートの危険表示など）と、演出と画面の重なりを確かめた。

## ブラウザ確認

ローカルの開発サーバーを Playwright の Chromium と WebKit で確認。API は架空の式・写真を返すモックで置き換え、実データは変更していない。

- 参加者・新郎新婦の 35 の状態（写真あり・なし、読み込み中、エラー、長い名前、確認シート、全画面表示、ランキングなど）を、両エンジン・幅 390px と 320px で撮影。横はみ出しとページの例外なし。文字 200% と幅 1280px も確認
- 管理画面の 34 の状態を、両エンジン・幅 1440px・390px・320px で撮影
- 演出はコマ撮り（40〜150ms 間隔）で確認。折り鶴は、送信の成功・遅い通信・失敗（409）・変更の短い版・長い名前と 1 文字の名前。儀式の演出は、スキップ（タップ・Escape・ボタン）と一度だけの再生
- 動きを減らす設定では、全画面の演出と折り鶴を出さず、結果の状態だけを表示
- 統合後に直したこと: 表紙と金屏風の小さな金の言葉が青海波の線に重なって読みにくい（背後に臙脂を敷いた）、幅 320px で表紙の言葉が「…ください／ました」で折れる、金屏風の終わりで舞台と下の画面が重なって濁る（溶けながら上へ抜けるようにした）

### 確かめられていないこと

- Playwright の WebKit は `perspective` を描かないため、金屏風が開く奥行きと、紙が折られる 3D は Chromium でしか確かめていない。iPhone の Safari の実機で確認する
- 古めの端末で 60fps が出るか（動かしているのは主に transform・opacity・小さな SVG）
- 実際の席次表 PDF と、実際の送信の進み具合の表示

エンジンによる検証であり、iPhone・Android の実機や式場の回線での測定ではない。

## リポジトリの検証コマンド

## 配信物

- 主な JS（`index-*.js`）は約 317KB（圧縮前）。席次表・投稿・アルバム・新郎新婦・管理の各画面は従来どおり遅延読み込み
- フォントは日本語が文字の範囲ごとに分割され、画面で使う文字の分だけ読み込む。ビルドの出力には全分割（woff2 と woff）が入るため、`dist/client` は約 43MB になる
