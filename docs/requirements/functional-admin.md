# 機能要件: 管理面

アプリケーションオーナー（管理者）が使う管理面の機能要件。

## 共通事項

- 管理面のすべての機能は、[FR-A-01](#fr-a-01-管理者ログインgoogle-認証) でログインした管理者だけが使える
- 管理者はすべてのテナントを操作できる（テナント横断）
- 管理操作は記録する（[NFR-19](non-functional.md)）

---

## FR-A-01 管理者ログイン（Google 認証）

- **概要**: 管理面には Google 認証でログインする。許可リストに登録された Google アカウントだけがログインできる。
- **詳細**:
  - Google アカウントで認証した後、そのアカウントのメールアドレスが管理者の許可リストに含まれるかを確認する
  - 許可リストにないアカウントはログインできず、アクセス拒否を表示する
  - ログアウトできる
  - 許可リストの管理方法（最初の管理者の登録、追加・削除）は [OQ-16](../open-questions.md)
- **受け入れ条件**:
  - [ ] 許可リストにある Google アカウントでログインできる
  - [ ] 許可リストにない Google アカウントではログインできない
  - [ ] 未ログインで管理面の URL に直接アクセスすると、ログイン画面に誘導される
  - [ ] 参加者のセッションでは管理面を利用できない
- **関連**: US-A-01 / SA-01 / [design/auth.md](../design/auth.md)

## FR-A-02 テナント一覧

- **概要**: 作成済みのテナントを一覧表示する。
- **詳細**:
  - 表示項目（仮置き）: テナント名、開催日、状態、作成日時
- **受け入れ条件**:
  - [ ] 作成済みのすべてのテナントが表示される
- **関連**: US-A-02 / SA-02

## FR-A-03 テナント作成

- **概要**: 結婚式ごとにテナントを作成する。
- **詳細**:
  - テナント ID は UUID をシステムが自動で採番する（手入力しない）
  - 入力項目（仮置き）: テナント名（結婚式の表示名）、開催日
  - 作成直後の状態は「準備中」（仮置き、[OQ-17](../open-questions.md)）
- **受け入れ条件**:
  - [ ] 作成すると UUID のテナント ID が採番される
  - [ ] テナント ID は他のテナントと重複しない
- **関連**: US-A-02 / SA-03 / [design/multi-tenancy.md](../design/multi-tenancy.md)

## FR-A-04 テナント設定（基本情報・状態）

- **概要**: テナントの基本情報と状態を変更する。
- **詳細**:
  - 基本情報（テナント名、開催日）を変更できる
  - 状態を切り替えられる: 準備中 / 公開中 / 終了（仮置き）
  - 状態ごとに参加者が何をできるか（参加・閲覧・投稿）は [OQ-17](../open-questions.md)
- **受け入れ条件**:
  - [ ] 変更した内容がユーザー画面に反映される
- **関連**: US-A-03 / SA-04

## FR-A-05 席次表 PDF の登録

- **概要**: テナントの席次表として PDF ファイルを登録する。
- **詳細**:
  - PDF ファイルのみ受け付ける
  - 再アップロードで差し替えられる
  - 登録済みの PDF を管理面でプレビューできる（仮置き）
- **受け入れ条件**:
  - [ ] PDF 以外のファイルは登録できない
  - [ ] 差し替えると、参加者には新しい PDF が表示される
- **関連**: US-A-03 / SA-04 / FR-G-05

## FR-A-06 料理のコース表の登録

- **概要**: テナントの料理のコース表の内容を登録する。
- **詳細**:
  - 入力方法（項目を順に入力する / 自由記述 / テナントごとに固定ページを用意する）は [OQ-11](../open-questions.md)
- **受け入れ条件**:
  - [ ] 登録した内容が、そのテナントの料理のコース表ページに表示される
- **関連**: US-A-03 / SA-04 / FR-G-06

## FR-A-07 参加 URL の発行・QR コード生成

- **概要**: テナントの参加 URL を発行し、受付で配布する QR コードを生成する。
- **詳細**:
  - 参加 URL は 1 テナントにつき 1 つ（テナント共通 QR 方式、[D-04](../open-questions.md)）。テナント ID と推測困難な参加トークンを含む
  - 参加 URL から QR コード画像を生成し、印刷用にダウンロードできる
  - 参加トークンに有効期間を設定できる。既定の期間は [OQ-02](../open-questions.md)
- **受け入れ条件**:
  - [ ] 発行した参加 URL・QR コードから参加できる（FR-G-01）
  - [ ] QR コードを印刷用の画像としてダウンロードできる
  - [ ] 有効期間外の参加トークンでは参加できない
- **関連**: US-A-04 / SA-05 / [design/auth.md](../design/auth.md)

## FR-A-08 参加 URL の再発行

- **概要**: 参加 URL が流出した場合などに、参加トークンを再発行する。
- **詳細**:
  - 再発行すると、それまでの参加トークンは無効になる（古い QR コードからは新しく参加できない）
  - 参加済みの参加者のセッションを維持するかは [OQ-02](../open-questions.md)（仮置き: 維持する）
- **受け入れ条件**:
  - [ ] 再発行後、古い参加 URL では新しく参加できない
  - [ ] 再発行後、新しい参加 URL で参加できる
- **関連**: US-A-04 / SA-05

## FR-A-09 ログの閲覧

- **概要**: システムのログを、テナント単位で絞り込んで確認できる。
- **詳細**:
  - 対象（仮置き）: エラー、参加、写真のアップロード、管理操作
  - 具体的な項目・保持期間、管理面の画面で見るか外部の監視ツールで見るかは [OQ-14](../open-questions.md)
- **受け入れ条件**:
  - [ ] テナントを指定してログを絞り込める
- **関連**: US-A-05 / SA-06 / NFR-18

## FR-A-10 メトリクスの監視

- **概要**: テナント単位と全体の利用状況、システムの状態を確認できる。
- **詳細**:
  - 指標の例（仮置き）: テナントごとの参加者数・写真枚数・いいね数・ストレージ使用量、全体のエラー率・応答時間
  - 具体的な指標とアラート条件は [OQ-14](../open-questions.md)
- **受け入れ条件**:
  - [ ] テナントごとの参加者数と写真枚数を確認できる
- **関連**: US-A-05 / SA-06 / NFR-18, NFR-20
