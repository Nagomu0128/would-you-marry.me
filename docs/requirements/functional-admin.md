# 機能要件: 管理面

アプリケーションオーナー（管理者）が使う管理面の機能要件。

## 共通事項

- 管理面のすべての機能は、[FR-A-01](#fr-a-01-管理者ログインgoogle-認証) でログインした管理者だけが使える
- 管理者はすべてのテナントを操作できる（テナント横断）
- 管理操作は記録する（[NFR-19](non-functional.md)）

---

## FR-A-01 管理者ログイン（Google 認証）

- **概要**: 管理面には Google 認証でログインする。許可リストに登録された Google アカウントだけがログインできる。
- **詳細**:
  - Google アカウントで認証した後、そのアカウントのメールアドレスが管理者の許可リストに含まれるかを確認する
  - 許可リストは設定ファイル・環境変数で管理する。管理面に管理者の追加・削除画面は作らない（D-22）
  - 許可リストにないアカウントはログインできず、アクセス拒否を表示する
  - ログアウトできる
- **受け入れ条件**:
  - [ ] 許可リストにある Google アカウントでログインできる
  - [ ] 許可リストにない Google アカウントではログインできない
  - [ ] 未ログインで管理面の URL に直接アクセスすると、ログイン画面に誘導される
  - [ ] 参加者・新郎新婦のセッションでは管理面を利用できない
- **関連**: US-A-01 / SA-01 / [design/auth.md](../design/auth.md)

## FR-A-02 テナント一覧

- **概要**: 作成済みのテナントを一覧表示する。
- **詳細**:
  - 表示項目: テナント名、開催日、現在の期間（[テナントの期間](../overview.md#テナントの期間)）、停止中かどうか、作成日時
- **受け入れ条件**:
  - [ ] 作成済みのすべてのテナントが表示される
  - [ ] 各テナントの現在の期間が、開催日から正しく表示される
- **関連**: US-A-02 / SA-02

## FR-A-03 テナント作成

- **概要**: 結婚式ごとにテナントを作成する。
- **詳細**:
  - テナント ID は UUID をシステムが自動で採番する（手入力しない）
  - 入力項目: テナント名（結婚式の表示名）、開催日。どちらも必須
  - テナントの期間は開催日から自動で決まる（D-23）
- **受け入れ条件**:
  - [ ] 作成すると UUID のテナント ID が採番される
  - [ ] テナント ID は他のテナントと重複しない
  - [ ] 開催日を入力しないと作成できない
- **関連**: US-A-02 / SA-03 / [design/multi-tenancy.md](../design/multi-tenancy.md)

## FR-A-04 テナント設定（基本情報・停止）

- **概要**: テナントの基本情報を変更し、必要なときにテナントを停止・再開する。
- **詳細**:
  - 基本情報（テナント名、開催日）を変更できる。開催日を変更すると、各期間もそれに合わせて変わる
  - テナントを手動で停止・再開できる（D-23）。停止中は、期間にかかわらず参加者・新郎新婦とも利用できない
  - 現在の期間と、データの削除予定日（開催日の 6 か月後）を表示する
  - 開催日前に参加者の画面を確認する方法は [OQ-21](../open-questions.md)
- **受け入れ条件**:
  - [ ] 変更した内容がユーザー画面に反映される
  - [ ] 停止すると、参加者・新郎新婦の画面にはエラー画面が表示される
  - [ ] 再開すると、その時点の期間に応じた状態に戻る
- **関連**: US-A-03, US-A-08 / SA-04

## FR-A-05 席次表 PDF の登録

- **概要**: テナントの席次表として PDF ファイルを登録する。
- **詳細**:
  - PDF ファイルのみ受け付ける
  - 再アップロードで差し替えられる
  - 登録済みの PDF を管理面でプレビューできる（仮置き）
- **受け入れ条件**:
  - [ ] PDF 以外のファイルは登録できない
  - [ ] 差し替えると、参加者には新しい PDF が表示される
- **関連**: US-A-03 / SA-04 / FR-G-05

## FR-A-06 料理のコース表の登録

- **概要**: テナントの料理のコース表として画像を登録する（D-17）。
- **詳細**:
  - 画像ファイル（JPEG / PNG など）を登録する
  - 複数枚を登録でき、表示する順番を指定できる（仮置き）
  - 差し替え・削除できる
- **受け入れ条件**:
  - [ ] 画像以外のファイルは登録できない
  - [ ] 登録した画像が、そのテナントの料理のコース表ページに表示される
- **関連**: US-A-03 / SA-04 / FR-G-06

## FR-A-07 参加 URL の発行・QR コード生成

- **概要**: テナントの参加 URL を発行し、受付で配布する QR コードを生成する。
- **詳細**:
  - 参加 URL は 1 テナントにつき 1 つ（D-04）。テナント ID と推測困難な参加トークンを含む
  - 準備期間中に発行し、QR コードを印刷しておける
  - 参加トークンで参加できるのは参加受付期間（開催日当日〜翌日）だけ。期間は開催日から自動で決まる（D-08）
  - 参加 URL から QR コード画像を生成し、印刷用にダウンロードできる
- **受け入れ条件**:
  - [ ] 発行した参加 URL・QR コードから、参加受付期間中に参加できる（FR-G-01）
  - [ ] 参加受付期間外は、参加 URL から参加できない
  - [ ] QR コードを印刷用の画像としてダウンロードできる
- **関連**: US-A-04 / SA-05 / [design/auth.md](../design/auth.md)

## FR-A-08 参加 URL の再発行

- **概要**: 参加 URL が流出した場合などに、参加トークンを再発行する。
- **詳細**:
  - 再発行すると、それまでの参加トークンは無効になる（古い QR コードからは新しく参加できない）
  - 参加済みの参加者のセッションは維持する（D-08）
- **受け入れ条件**:
  - [ ] 再発行後、古い参加 URL では新しく参加できない
  - [ ] 再発行後、新しい参加 URL で参加できる
  - [ ] 再発行しても、参加済みの参加者はそのまま使い続けられる
- **関連**: US-A-04 / SA-05

## FR-A-09 ログ

- **概要**: システムのログ、エラー率、応答時間は外部の監視ツールで確認する（D-20）。
- **詳細**:
  - ログにはテナント ID を付け、外部の監視ツールでテナント単位に絞り込めるようにする
  - 対象: エラー、参加、写真のアップロード・削除、管理操作（仮置き）
  - 監視画面（SA-06）から外部の監視ツールを開けるようにする（仮置き）
  - 使う監視ツールとアラート条件は技術選定時に決める（[design/architecture.md](../design/architecture.md)）
- **受け入れ条件**:
  - [ ] 外部の監視ツールで、テナント ID を指定してログを絞り込める
- **関連**: US-A-05 / SA-06 / NFR-18

## FR-A-10 利用状況

- **概要**: テナントごとの利用状況を管理面で確認できる（D-20）。
- **詳細**:
  - 項目: 参加者数、写真枚数、いいね数、保存容量
  - テナント詳細（SA-04）ではそのテナントの値を、監視画面（SA-06）では全テナントの一覧を表示する
- **受け入れ条件**:
  - [ ] テナントごとの参加者数・写真枚数・いいね数・保存容量を確認できる
- **関連**: US-A-05 / SA-04, SA-06 / NFR-20

## FR-A-11 写真の削除（モデレーション）

- **概要**: 管理者は、テナントの写真を一覧して削除できる（D-14）。
- **詳細**:
  - テナントの写真を新しい順に一覧表示する。投稿者のニックネームといいね数も表示する
  - 削除の前に確認を求める
  - 削除した写真は、参加者・新郎新婦の画面から消える。その写真へのいいねも削除する
  - 非表示（後から戻せる状態）の機能は設けない
- **受け入れ条件**:
  - [ ] 削除した写真が、タイムライン・ランキング・新郎新婦用ページに表示されなくなる
  - [ ] 削除の操作が記録される（NFR-19）
- **関連**: US-A-06 / SA-07

## FR-A-12 新郎新婦用 URL・パスコードの発行

- **概要**: 新郎新婦用ページに入るための専用 URL とパスコードを発行する（D-18）。
- **詳細**:
  - 専用 URL は 1 テナントにつき 1 つ。テナント ID と推測困難なトークンを含む
  - パスコードはシステムが自動で生成する（仮置き: 英数字 8 文字）。発行した時にだけ画面に表示する
  - 管理者は、専用 URL とパスコードを別々の手段で二人に伝える（仮置き）
  - 再発行すると、古い URL とパスコードは無効になり、新郎新婦のセッションも無効になる（仮置き）
- **受け入れ条件**:
  - [ ] 発行した専用 URL とパスコードで、新郎新婦用ページに入れる（FR-C-01）
  - [ ] 再発行後、古い URL とパスコードでは入れない
- **関連**: US-A-07 / SA-05 / [design/auth.md](../design/auth.md)

## FR-A-13 データの自動削除

- **概要**: 開催日の 6 か月後に、システムがテナントのデータを自動で削除する（D-19）。
- **詳細**:
  - 削除するもの: 写真（オリジナル・縮小画像）、いいね、参加者、席次表、コース表の画像、参加 URL、新郎新婦用 URL
  - テナント自体（テナント名・開催日）は管理面の履歴として残し、削除済みと表示する（仮置き）
  - 削除予定日はテナント詳細（SA-04）に表示する
- **受け入れ条件**:
  - [ ] 開催日の 6 か月後に、テナントの写真などのデータとファイルが削除される
  - [ ] 削除後は、参加者・新郎新婦とも利用できない
- **関連**: SA-04 / NFR-17
