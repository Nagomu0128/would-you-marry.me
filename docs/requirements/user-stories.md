# ユーザーストーリー

「**誰が**、**どうやって（どういう条件で）**、**何ができる**」の形式で書く。
参加者のストーリーはプロダクトオーナーの原文をもとにしている。

## 参加者（ゲスト）

前提: 受付時に QR コードが配布され、その QR コードから Web アプリケーションにアクセスする。

| ID | 誰が | どうやって（条件） | 何ができる |
|---|---|---|---|
| US-G-01 | 参加者 | 受付で配布された QR コードを読み取ることで | 匿名認証でログインし、セッショントークンをブラウザに保存する |
| US-G-02 | 参加者 | ニックネームを登録した後に | ホームページを閲覧できる |
| US-G-03 | 参加者 | ホームページから | オンライン席次表・料理のコース表・共有フォトアルバム・フォトアップロードの各ページにアクセスできる |
| US-G-04 | 参加者 | オンライン席次表ページで | 席次表（PDF）をインライン表示で閲覧できる |
| US-G-05 | 参加者 | 料理のコース表ページで | 料理のコース表（静的ページ）を閲覧できる |
| US-G-06 | 参加者 | フォトアップロードページで | 写真をアップロードし、共有フォトアルバムに投稿できる |
| US-G-07 | 参加者 | 共有フォトアルバムページで | 「タイムライン」と「いいね数ランキング」の 2 つのタブを閲覧できる |
| US-G-08 | 参加者 | 共有フォトアルバムのタイムラインタブで | すべての参加者が投稿した写真を閲覧し、他の参加者の写真に「いいね」を付け、保存できる |
| US-G-09 | 参加者 | 共有フォトアルバムのランキングタブで | いいね数ランキング順に写真を閲覧し、保存できる |

### 原文からの解釈

1. **US-G-03〜06**: 原文ではホームからアクセスできるページの一覧として書かれている。各ページでできることを個別のストーリーに分けた。
   US-G-06 の「写真をアップロードし、共有フォトアルバムに投稿できる」は、ページ名「フォトアップロードページ」からの解釈。
2. **US-G-09**: 原文は「共有フォトアルバムページの**タイムラインタブ**で参加者は、いいね数ランキング**潤**の写真を閲覧・保存することができる」。
   「潤」は「順」の誤記、「タイムラインタブ」は「ランキングタブ」の誤記と解釈した。
3. **保存**: 写真を自分の端末にダウンロードすることと解釈した。保存する画像の画質などは [OQ-19](../open-questions.md)。
4. **いいね**: 原文は「他参加者のアップロードした写真に "いいね"」。自分の写真へのいいね可否などは [OQ-09](../open-questions.md)。

## 管理者（アプリケーションオーナー）

| ID | 誰が | どうやって（条件） | 何ができる |
|---|---|---|---|
| US-A-01 | アプリケーションオーナー権限を持つ人 | Google 認証でログインすることで | 管理面を利用できる。権限を持たない Google アカウントではログインできない |
| US-A-02 | 管理者 | 管理面で | 結婚式ごとにテナントを作成できる。テナントは UUID で識別される |
| US-A-03 | 管理者 | 管理面で | テナントの設定（席次表 PDF、料理のコース表など）を行える |
| US-A-04 | 管理者 | 管理面で | テナントの参加 URL を発行できる。参加 URL は QR コードにして受付で配布する |
| US-A-05 | 管理者 | 管理面で | ログやメトリクスを監視できる |

### 原文からの解釈

1. **US-A-03**: 原文は「テナント設定」。ユーザー画面にはコンテンツを編集する機能がないため、席次表 PDF と料理のコース表は管理面で登録すると解釈した。
   新郎新婦が自分で登録できるようにするかは [OQ-12](../open-questions.md)。
2. **US-A-04**: 原文は「URL の発行」。テナント共通の参加 URL（1 テナントにつき 1 つ）を発行することと解釈した（[D-04](../open-questions.md)）。
