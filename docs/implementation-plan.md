# 実装計画・進捗

docs/ の要件・設計を実装するためのタスク分割と進捗。オーケストレーター（Claude Opus）がタスクを分割・レビュー・マージし、実装は subagent（[.claude/agents/implementer.md](../.claude/agents/implementer.md)、Sonnet）が行う。

- 期限: 2026-10-31（土）の結婚式（D-33）。受付で配る QR コードは 1 週間前（10/24 頃）に印刷するため、**管理面のテナント作成と参加 URL・QR コードの発行（T02・T03・T10・T11・T16・T17 の SA-05・T20）を 10/23 までに本番へ出す**
- 実機での検証（T19）は検証環境を作らず、本番ドメインで行う
- 進め方: 1 タスク = 1 ブランチ（git worktree）。実装 → オーケストレーターのレビュー（仕様との突き合わせ、lint・型検査・テスト・ビルド）→ main にマージ
- 状態: `未着手` / `作業中` / `レビュー中` / `完了`

## 共通の約束

subagent への指示（[.claude/agents/implementer.md](../.claude/agents/implementer.md)）に加えて、タスクをまたいで守ること。

- パッケージ名: `@wym/shared`、`@wym/db`、`@wym/ui`、`@wym/guest`、`@wym/admin`。packages はビルドせず、TypeScript のソースをそのまま参照する
- ローカル開発では、2 つの Worker が同じ D1・R2 のローカル状態（リポジトリ直下の `.wrangler/state`）を使う
- 開発サーバーのポート: guest 5173、admin 5174
- 依存パッケージは T01 でまとめて入れる。後のタスクで追加するときは報告し、マージ時にロックファイルの衝突をオーケストレーターが解消する
- 文言・上限値・エラーコードは 1 か所に集める（messages/ja.ts、limits.ts、errors.ts）

## レビューの観点（オーケストレーター）

1. 仕様との突き合わせ: 対応する FR / API / 画面の記述を 1 行ずつ確認する
2. テナント分離: tenant_id の絞り込み、セッションとテナントの一致、他テナントの ID を指定したときの拒否
3. テスト: 受け入れ条件・境界値がテストにあるか。テストが実装に合わせて弱められていないか
4. `pnpm install && pnpm lint && pnpm typecheck && pnpm test && pnpm build` を自分で実行して通ること
5. 個人情報をログに出していないこと、文言・定数が直書きされていないこと
